# Hezky česky — čeština pro 3. třídu

Тренажёр по чешскому языку за 3 класс.

- 511 вопросов в 3 уровнях сложности: с вариантами ответа и со свободным вводом.
- Открытая регистрация детей и родителей. Родитель видит только своих детей.
- На каждом уровне свой ранг 0–10, ранги привязаны к игрокам ФК Барселона.
- Статистика для родителя.

Стек: Symfony 8.1, PHP 8.5 (php-fpm), nginx, SQLite. Два контейнера в Docker Compose: `app` и `web`.
Инструкция для пользователей (родителей и детей): [čeština](docs/USER_GUIDE.cs.md) · [English](docs/USER_GUIDE.en.md).
В приложении это раздел **Nápověda / Help** (`/cs/help`, `/en/help`), он открывается и без входа.
Для AI-агентов есть отдельный документ: [AGENTS.md](AGENTS.md).

## Как поднять приложение

### 1. Что нужно

- Docker 20+ с плагином Compose v2 (проверка: `docker compose version`).
- Свободный порт 8080 (можно взять другой, см. ниже).
- PHP, Composer и nginx на машине **не нужны**: всё собирается внутри образов.

### 2. Скачать и запустить

```bash
git clone git@github.com:dpotekhin-prog/hezky-cesky.git
cd hezky-cesky
docker compose up -d --build
```

Поднимаются два контейнера:

| Сервис | Что внутри |
|---|---|
| `app` | PHP-FPM + Symfony, база SQLite в volume |
| `web` | nginx на порту 8080: отдаёт статику и передаёт запросы в `app` |

Первая сборка занимает 1–3 минуты. При каждом старте `app` сам:
1. при первом запуске генерирует секрет приложения;
2. применяет миграции БД;
3. загружает вопросы из `content/`.

`web` стартует только после этого.

### 3. Проверить, что всё поднялось

```bash
docker compose ps
# app ... Up (healthy)
# web ... Up            0.0.0.0:8080->80/tcp

docker compose logs app | grep 'Topics:'
# [OK] Topics: 11, questions: 511, deactivated: 0
```

Если `app` не становится `healthy`, причина будет в `docker compose logs app` (см. «Если что-то не так»).

### 4. Открыть

```bash
xdg-open http://localhost:8080     # macOS: open http://localhost:8080
```

### 5. Первые шаги

1. **Registrace** → «Jsem rodič» → придумать логин и пароль. После регистрации откроется кабинет **Pro rodiče**.
2. В кабинете **Vytvořit účet dítěte** → логин и пароль ребёнка. Ребёнок сразу привязан к вам.
3. Выйти (**Odhlásit**) и войти под ребёнком, можно заниматься.

Другие варианты:
- **Ребёнок зарегистрировался сам** («Jsem žák / žákyně»): он видит в «Moje výsledky» **код pro rodiče**,
  а родитель вводит этот код в «Připojit existující účet dítěte». К одному ребёнку можно привязать двух родителей.
- **Ребёнок забыл пароль:** Pro rodiče → ребёнок → «Nové heslo».
- **Родитель из консоли** (или сброс пароля родителю). Пароль команда спросит интерактивно:
  ```bash
  docker compose exec app su -s /bin/sh www-data -c 'php bin/console app:user:parent rodic'
  ```

### 6. Обновление

```bash
git pull
docker compose up -d --build
```

Результаты сохраняются: база лежит в volume, новые миграции применяются при старте.

**Обновление с версии на Apache** (до коммита `e3ac3e1`) делается той же командой. Вместо одного контейнера станет два (`app` + `web`), данные сохранятся. После обновления:
- всех один раз разлогинит, потому что сгенерируется новый секрет;
- уже существующих детей нужно один раз привязать к родителю по коду (шаг 5).

## Повседневные команды

| Что | Команда |
|---|---|
| Остановить | `docker compose stop` |
| Запустить снова | `docker compose start` |
| Логи | `docker compose logs -f app web` |
| Перечитать вопросы после правки YAML | `docker compose restart` |
| Другой порт | `APP_PORT=9000 docker compose up -d` |
| Бэкап базы и секрета | `docker compose cp app:/var/www/app/var/data ./backup-$(date +%F)` |
| Удалить всё вместе с результатами | `docker compose down -v` |

База лежит в Docker volume `<папка>_app_data` и переживает пересборку и перезапуск. Удаляет её только `down -v`.

Чтобы открыть приложение с другого устройства в домашней сети (например, с планшета ребёнка), зайдите на
`http://<IP-компьютера>:8080`. Если порт закрыт, откройте его в файрволе.
Для развёртывания на сервере см. раздел «Безопасность и сервер».

## Безопасность и сервер

Что уже сделано:
- **Секрет приложения** генерируется при первом запуске и хранится в volume рядом с базой (`var/data/.app_secret`, права 600).
  Свой можно задать через `APP_SECRET=...`.
- **Перебор паролей:** после 5 неудачных попыток вход блокируется на 15 минут.
- **Лимиты:** не больше 5 регистраций в час с одного IP и 10 попыток ввести код ребёнка в час.
- **CSRF-защита** всех форм и выхода.
- **Cookie сессии** с `HttpOnly` и `SameSite=Lax`; `Secure` включается автоматически при HTTPS.
- **Заголовки** `Content-Security-Policy`, `X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy`.
  Версии nginx и PHP скрыты.
- **Изоляция семей:** родитель видит и меняет только своих детей, чужая страница отвечает 404.
- **Код в контейнере:** доступен только `public/`, прямой вызов `.php` файлов закрыт.
- **Зависимости** проверены `composer audit`, уязвимостей нет.

Чек-лист перед публикацией в интернет:
1. **HTTPS обязателен.** Поставьте перед `web` прокси с TLS (Caddy, Traefik, nginx с certbot) или добавьте TLS в `docker/nginx.conf`.
   HSTS включайте на этом HTTPS-уровне.
2. Если прокси стоит перед контейнером `web`, задайте его адрес: `TRUSTED_PROXIES=172.16.0.0/12`. Тогда работают правильный IP
   клиента для лимитов и определение HTTPS. Без прокси переменную не трогайте.
3. `DEFAULT_URI=https://ваш-домен` — используется при генерации ссылок вне HTTP-запроса.
4. Порт: открывайте наружу только 443 у прокси; порт `web` можно привязать к localhost (`127.0.0.1:8080:80` в `compose.yaml`).
5. Бэкап базы и секрета: `docker compose cp app:/var/www/app/var/data ./backup-$(date +%F)`.
6. Периодически обновляйте образы (`docker compose build --pull`) и проверяйте зависимости `composer audit`.

## Правила

- **Вопросы не повторяются.** В обычном режиме каждый вопрос выпадает ребёнку **один раз**. Сохраняется каждый ответ: что введено, правильно ли, когда.
- **Ошибки.** Вопросы с ошибкой возвращаются только в режиме **Opravit chyby** (кнопка на главной).
- **Ранг.** Считается отдельно для каждого уровня:
  `очки = правильные − 0.5 × ошибки`, `ранг = floor(10 × очки / число вопросов уровня)`.
  От ранга 0 к 10: Balde → Cubarsí → Fermín → Gavi → Raphinha → Pedri → Lamine Yamal → Puyol → Xavi → Iniesta → **Messi**.
  Список игроков — в `content/players.yaml`.
- **Открытие уровней.** Уровни 2 и 3 открываются, когда на предыдущем уровне пройдено ≥ 80 % вопросов и правильных ≥ 70 %.
  Пороги — константы в `src/Service/StatsProvider.php`. Начатый уровень остаётся открытым.

## Вопросы

Темы описаны в `content/topics.yaml`, вопросы лежат в `content/questions/*.yaml`. Формат вопроса:

```yaml
- id: "l1-uu-001"          # стабильный уникальный id, не менять
  topic: "u-u"
  level: 1
  type: "input"            # или "choice" с options + correct
  prompt: "Doplň ú nebo ů a napiš celé slovo: d_m"
  answers: ["dům"]         # все допустимые ответы; регистр и пробелы не важны, диакритика важна
  explanation: { cs: "…", en: "…" }
```

Папка `content/` смонтирована в контейнер. После правки YAML достаточно `docker compose restart`.
Импорт находит вопрос по `id` и обновляет его. Вопрос, удалённый из YAML, деактивируется, а история ответов по нему остаётся.
Если в YAML ошибка, контейнер не стартует, а причина видна в `docker compose logs app`.

## Разработка

Нужны зависимости, включая dev-пакеты (ставятся через Docker):

```bash
docker run --rm -u $(id -u):$(id -g) -v $PWD:/app -w /app -e COMPOSER_HOME=/tmp/c composer:2 composer install
```

Dev-сервер с автоподхватом изменений в коде, без пересборки образа, на http://localhost:8000:

```bash
docker run --rm -it -u $(id -u):$(id -g) -v $PWD:/app -w /app -e APP_SECRET=dev -p 8000:8000 php:8.5-cli \
  sh -c 'mkdir -p var/data && php bin/console d:m:m -n && php bin/console app:questions:import && php -S 0.0.0.0:8000 -t public'
```

Линтеры, миграции и правила для изменений описаны в [AGENTS.md](AGENTS.md).

## Если что-то не так

| Симптом | Что делать |
|---|---|
| `port is already allocated` | Порт 8080 занят: запустите на другом, `APP_PORT=9000 docker compose up -d` |
| Контейнер перезапускается по кругу | `docker compose logs app`: чаще всего это ошибка в YAML вопросов, в логе будут файл и номер вопроса |
| Ошибка 500 | `docker compose logs app \| grep -i critical` |
| Забыли пароль родителя | Повторите команду из шага 4 с тем же именем |
| Ребёнок забыл пароль | Родитель задаёт новый: **Pro rodiče** → ребёнок → «Nové heslo» |
| «Příliš mnoho pokusů…» при входе | 5 неверных паролей подряд — подождите 15 минут |
| «Příliš mnoho účtů…» при регистрации | Лимит 5 регистраций в час с одного IP |
